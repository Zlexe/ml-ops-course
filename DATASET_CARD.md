# Dataset Card: Bank Marketing

## Происхождение

- **Источник:** Moro, S., Cortez, P., Rita, P. (2014). A data-driven approach to predict the success of bank telemarketing. Decision Support Systems, 62, 22–31.
- **Репозиторий:** UCI Machine Learning Repository, набор «Bank Marketing» (`bank-full.csv`).
- **Лицензия:** CC BY 4.0. Использование в учебном проекте с указанием источника.
- **Версия файла:** md5 `e6b0ca77f3f200ec5428e04dd104da53`, размер 4 610 348 байт. Хранится в DVC (`data/raw/bank-full.csv.dvc`), в Git — только метаданные.

## Состав

- 45 211 строк, 17 колонок, разделитель `;`.
- Целевой признак: `y` (yes/no) — согласился ли клиент на срочный депозит.
- Баланс классов: no 88.3%, yes 11.7%.
- Пропусков и дубликатов нет. Значение `unknown` в `job`, `education`, `contact`, `poutcome` — отдельная категория, а не пропуск.

| Признак | Тип | Описание |
|---|---|---|
| age | int | возраст клиента |
| job | категориальный | род занятий |
| marital | категориальный | семейное положение |
| education | категориальный | образование |
| default | категориальный | наличие просроченного кредита |
| balance | int | средний годовой баланс, евро |
| housing | категориальный | наличие ипотеки |
| loan | категориальный | наличие персонального кредита |
| contact | категориальный | тип связи с клиентом |
| day, month | int, категориальный | день и месяц последнего контакта |
| duration | int | длительность последнего звонка, секунды |
| campaign | int | число контактов в текущей кампании |
| pdays | int | дней с предыдущей кампании, -1 — не звонили |
| previous | int | число контактов до текущей кампании |
| poutcome | категориальный | результат предыдущей кампании |

## Исключённые признаки

- **`duration`** исключён из всех моделей. Длительность звонка становится известна только после звонка, поэтому использовать её для прогноза до звонка нельзя. Это утечка целевой переменной. Модель с ней показала бы нереалистично высокое качество.

## Правила разбиения

- Стратифицированное разбиение по `y`, `random_state=42`.
- Train 60% (27 126 строк), validation 20% (9 042), test 20% (9 043).
- Hyperparameters подбираются только по validation.
- Test используется один раз, для итоговой оценки модели `lgbm_v2`.

Реализация: `src/ml_ops_course/data.py`, функция `split_data`.

## Препроцессинг

- **v1:** `duration` удаляется; числовые признаки (`age`, `balance`, `day`, `campaign`, `pdays`, `previous`) масштабируются `StandardScaler`; категориальные кодируются `OneHotEncoder(handle_unknown="ignore")`.
- **v2:** то же, плюс признак `previously_contacted` (1, если `pdays != -1`), а `pdays` удаляется. Это отделяет факт предыдущего контакта от значения давности.

Реализация: `src/ml_ops_course/preprocessing.py`. Препроцессинг входит в сохранённый `Pipeline`, поэтому сервис применяет те же преобразования, что и при обучении.

## Известные ограничения данных

- Данные относятся к телемаркетинговой кампании одного банка в Португалии (2008–2010), переносимость на другие банки и страны не проверялась.
- Сильный дисбаланс классов: accuracy малоинформативна, основные метрики — ROC-AUC, PR-AUC и F1.
- `poutcome = unknown` и `pdays = -1` у большинства строк: клиенты, с которыми раньше не работали, составляют основную часть выборки.
- Признак `day` без года и с неполной информацией о сезонности.
- Этическая сторона: модель, если её применять для отбора клиентов, может усиливать неравенство доступа к продуктам. Использовать только как учебный пример.
